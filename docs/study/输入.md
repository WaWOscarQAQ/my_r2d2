### 2. 每轮前发送的固定上下文输入

位于 [`full_stack_bootstrap.yaml`](/home/oscar/ROS/my_r2d2/config/nav2_sequences/full_stack_bootstrap.yaml:10)，共有三个步骤：

1. `valid_initial_pose`：向 `/initialpose` 发送合法初始位姿
2. `seed_odometry`：向 `/odom` 发送合法里程计
3. `context_clear_scan`：每轮向 `/scan` 发送一帧无遮挡 LaserScan

启动阶段执行前两个；每轮正式 fuzz payload 之前执行三个。这些目前是固定上下文，不参与 `mutation.rs` 的变异。

### 3. LaserScan 发送调度输入

位于目录：

[`config/nav2_seeds/schedules`](/home/oscar/ROS/my_r2d2/config/nav2_seeds/schedules)

目前有 10 个 `.sched` 文件。每行包含：

```text
duration_sec period_ms burst_count burst_gap_ms max_publishes stamp_mode
```

它们控制 `/scan` 的持续时间、发送周期、burst 数量、burst 间隔、最大发布次数和时间戳模式。仅在传入 `--seed-dir config/nav2_seeds` 时加载；加载位置见 [`nav2_costmap_e2e.rs`](/home/oscar/ROS/my_r2d2/examples/nav2_costmap_e2e.rs:821)。

### 4. 已存在但当前没有进入主 fuzz pool 的输入

[`config/nav2_seeds/scans`](/home/oscar/ROS/my_r2d2/config/nav2_seeds/scans) 中有四个历史 LaserScan payload：

- `canonical.txt`
- `bug_round_25.txt`

但当前 e2e 主循环明确只加载 `schedules/`，**这些 scan 文件没有预填进 payload pool**。当前 payload pool 初始为空，运行时新生成 payload；只有触发新状态或 crash 的 payload 才会保留在内存池中。

另外，[`nav2_params_full_stack_fuzz.yaml`](/home/oscar/ROS/my_r2d2/config/nav2_params_full_stack_fuzz.yaml) 是 Nav2 启动配置，不属于每轮随机变异输入。
