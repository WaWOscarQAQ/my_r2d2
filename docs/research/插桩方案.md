# Nav2 通用插桩方案：Clang TSAN + SanitizerCoverage

这份方案描述的是“脱离具体 fuzz 项目以后，如何在同类系统上对 Nav2 本身进行插桩构建”。它不依赖任何项目内脚本、专用 harness 或私有目录结构；核心目标是让别人拿到一份 Nav2 源码，也能在自己的 ROS 2 workspace 中编译出可运行、可检测 data race、可输出 SanitizerCoverage 覆盖率文件的 Nav2。

## 1. 目标

在不修改系统 ROS 安装、不把结果安装到 `/opt/ros` 的前提下，构建本地插桩版 Nav2：

- 使用 Clang/LLVM 18 编译 Nav2。
- 使用 ThreadSanitizer 检测 data race / lock-order-inversion。
- 使用 LLVM SanitizerCoverage 采集 PC/edge 覆盖信息。
- 所有构建、安装、日志产物都放在用户自己的 workspace 中。

最终产物建议放在：

```text
$NAV2_WS/build_sancov
$NAV2_WS/install_sancov
$NAV2_WS/log_sancov
```

如果只需要 TSAN，不需要覆盖率，则可以放在：

```text
$NAV2_WS/build_tsan
$NAV2_WS/install_tsan
$NAV2_WS/log_tsan
```

## 2. 环境要求

该方案面向当前同类系统：

- Ubuntu
- ROS 2 lyrical，系统 underlay 位于 `/opt/ros/lyrical`
- Clang/LLVM 18
- colcon
- Nav2 源码

检查工具版本：

```bash
clang-18 --version
clang++-18 --version
opt-18 --version
g++ --version
colcon version-check
rosdep --version
git --version
```

必要依赖示例：

```bash
sudo apt update
sudo apt install -y \
  clang-18 clang++-18 llvm-18 llvm-18-dev lld-18 \
  build-essential cmake git \
  python3-colcon-common-extensions python3-rosdep python3-vcstool
```

注意：这里安装的是编译工具链和依赖包，不是把 Nav2 插桩结果安装进系统。

## 3. 准备 Nav2 workspace

可以新建一个完全独立的 workspace：

```bash
export ROS_DISTRO=lyrical
export ROS_SETUP=/opt/ros/$ROS_DISTRO/setup.bash

mkdir -p ~/nav2_instrument_ws/src
cd ~/nav2_instrument_ws
export NAV2_WS=$PWD
```

把 Nav2 源码放进 `$NAV2_WS/src/navigation2`。如果需要从 GitHub 获取源码，可以按目标 ROS 版本选择对应分支：

```bash
cd "$NAV2_WS/src"
git clone -b <branch-for-your-ros-distro> https://github.com/ros-navigation/navigation2.git
```

如果已经有 Nav2 源码，也可以直接复制或软链接到：

```text
$NAV2_WS/src/navigation2
```

安装依赖：

```bash
cd "$NAV2_WS"
source "$ROS_SETUP"
rosdep install --from-paths src --ignore-src -r -y
```

## 4. 通用编译参数

Clang 18：

```bash
export CC=/usr/bin/clang-18
export CXX=/usr/bin/clang++-18
export GCC_INSTALL_DIR="$(dirname "$(g++ -print-file-name=libstdc++.so)")"
export CLANG_GCC_FLAG="--gcc-install-dir=$GCC_INSTALL_DIR"
```

使用 `--gcc-install-dir` 的原因是：Clang 编译 C++ 时仍需要正确找到当前系统的 GCC/libstdc++ 运行库。当前系统使用 g++ 15，因此这个参数可以避免 C++ 标准库路径错配。

## 5. TSAN-only 构建

如果只需要 data race 检测，不需要 SanitizerCoverage 覆盖率，使用 TSAN-only 构建：

```bash
cd "$NAV2_WS"
source "$ROS_SETUP"

colcon build --symlink-install \
  --base-paths "$NAV2_WS/src/navigation2" \
  --build-base "$NAV2_WS/build_tsan" \
  --install-base "$NAV2_WS/install_tsan" \
  --log-base "$NAV2_WS/log_tsan" \
  --cmake-clean-cache \
  --packages-up-to nav2_bringup \
  --cmake-args \
    -DBUILD_TESTING=OFF \
    -DCMAKE_BUILD_TYPE=RelWithDebInfo \
    -DCMAKE_C_COMPILER=/usr/bin/clang-18 \
    -DCMAKE_CXX_COMPILER=/usr/bin/clang++-18 \
    "-DCMAKE_C_FLAGS=-O1 -g -w -Wno-error -fno-omit-frame-pointer -fsanitize=thread" \
    "-DCMAKE_CXX_FLAGS=-O1 -g -w -Wno-error -fno-omit-frame-pointer -fsanitize=thread $CLANG_GCC_FLAG" \
    "-DCMAKE_EXE_LINKER_FLAGS=-fsanitize=thread" \
    "-DCMAKE_SHARED_LINKER_FLAGS=-fsanitize=thread" \
    "-DCMAKE_MODULE_LINKER_FLAGS=-fsanitize=thread"
```

构建完成后，本地插桩版 Nav2 setup 文件是：

```bash
source "$NAV2_WS/install_tsan/setup.bash"
```

## 6. TSAN + SanitizerCoverage 构建

这是我们用于 full-stack fuzz 的成功路线。它同时打开：

- `-fsanitize=thread`
- `-fsanitize-coverage=trace-pc-guard,pc-table`

构建命令：

```bash
cd "$NAV2_WS"
source "$ROS_SETUP"

colcon build --symlink-install \
  --base-paths "$NAV2_WS/src/navigation2" \
  --build-base "$NAV2_WS/build_sancov" \
  --install-base "$NAV2_WS/install_sancov" \
  --log-base "$NAV2_WS/log_sancov" \
  --cmake-clean-cache \
  --packages-up-to nav2_bringup \
  --cmake-args \
    -DBUILD_TESTING=OFF \
    -DCMAKE_BUILD_TYPE=RelWithDebInfo \
    -DCMAKE_C_COMPILER=/usr/bin/clang-18 \
    -DCMAKE_CXX_COMPILER=/usr/bin/clang++-18 \
    "-DCMAKE_C_FLAGS=-O1 -g -w -Wno-error -fno-omit-frame-pointer -fsanitize=thread -fsanitize-coverage=trace-pc-guard,pc-table -DSANITIZER_COVERAGE_RUN=1" \
    "-DCMAKE_CXX_FLAGS=-O1 -g -w -Wno-error -fno-omit-frame-pointer -fsanitize=thread -fsanitize-coverage=trace-pc-guard,pc-table -DSANITIZER_COVERAGE_RUN=1 $CLANG_GCC_FLAG" \
    "-DCMAKE_EXE_LINKER_FLAGS=-fsanitize=thread" \
    "-DCMAKE_SHARED_LINKER_FLAGS=-fsanitize=thread" \
    "-DCMAKE_MODULE_LINKER_FLAGS=-fsanitize=thread"
```

构建完成后，本地插桩版 Nav2 setup 文件是：

```bash
source "$NAV2_WS/install_sancov/setup.bash"
```

这一步不会写入 `/opt/ros`。`--install-base "$NAV2_WS/install_sancov"` 明确指定了本地安装目录。

## 7. 是否需要插桩 ROS 2 client library

最小可用方案是只插桩 Nav2 源码包，底层 ROS 2 仍使用 `/opt/ros/lyrical` 中的系统库。这已经可以发现 Nav2 自身代码中的 TSAN 问题，也能采集 Nav2 二进制和 Nav2 动态库的 SanitizerCoverage。

如果研究目标需要覆盖 `rcl`、`rclcpp`、`rclcpp_lifecycle` 或 executor/callback 调度内部路径，可以额外做一个本地 ROS overlay，把这些 ROS 2 client library 也用相同参数编译到本地前缀，例如：

```text
$ROS_OVERLAY_WS/install_sancov
```

运行时 source 顺序应为：

```bash
source /opt/ros/lyrical/setup.bash
source "$ROS_OVERLAY_WS/install_sancov/setup.bash"
source "$NAV2_WS/install_sancov/setup.bash"
```

这个增强层仍然不需要改 `/opt/ros`，本质上只是本地 overlay。若只报告 Nav2 插桩方案，可以把它作为可选项，不作为必要条件。

## 8. 运行插桩版 Nav2

创建输出目录：

```bash
export RUN_OUT="$NAV2_WS/run_sancov_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$RUN_OUT/tsan" "$RUN_OUT/sancov" "$RUN_OUT/ros_logs"
```

设置运行时环境：

```bash
source /opt/ros/lyrical/setup.bash
source "$NAV2_WS/install_sancov/setup.bash"

export ROS_DOMAIN_ID=42
export ROS2CLI_NO_DAEMON=1
export ROS_LOG_DIR="$RUN_OUT/ros_logs"
```

设置 TSAN 与 SanitizerCoverage 输出：

```bash
export TSAN_OPTIONS="halt_on_error=0:exitcode=0:history_size=7:second_deadlock_stack=1:report_signal_unsafe=0:symbolize=0:log_path=$RUN_OUT/tsan/tsan:coverage=1:coverage_dir=$RUN_OUT/sancov"
```

启动 Nav2：

```bash
setarch x86_64 -R ros2 launch nav2_bringup bringup_launch.py \
  map:=/path/to/map.yaml \
  params_file:=/path/to/nav2_params.yaml \
  use_sim_time:=False \
  use_composition:=False \
  autostart:=True
```

说明：

- `setarch x86_64 -R` 用于关闭 ASLR，TSAN/coverage 结果更稳定，也能避免部分 TSAN 环境下的地址映射问题。
- `coverage=1` 和 `coverage_dir=...` 会让 Clang sanitizer runtime 输出 `.sancov` 覆盖率文件。
- `log_path=...` 会把 TSAN 报告写到 `$RUN_OUT/tsan/tsan.*`。
- `symbolize=0` 可以让运行期更稳，后续再用符号工具离线解析地址。

如果 `ros2 launch` 的 Python 入口因为 TSAN runtime 加载问题启动失败，可以尝试显式预加载 Clang TSAN runtime：

```bash
export CLANG_TSAN_RT=/usr/lib/llvm-18/lib/clang/18/lib/linux/libclang_rt.tsan-x86_64.so
LD_PRELOAD="$CLANG_TSAN_RT" setarch x86_64 -R ros2 launch nav2_bringup bringup_launch.py \
  map:=/path/to/map.yaml \
  params_file:=/path/to/nav2_params.yaml \
  use_sim_time:=False \
  use_composition:=False \
  autostart:=True
```

若 C++ Nav2 节点已经通过 `-fsanitize=thread` 链接 TSAN，一般不需要给每个 Nav2 节点额外 `LD_PRELOAD`。

## 9. 刷新和收集 SanitizerCoverage

SanitizerCoverage 通常会在进程退出时写出 `.sancov` 文件。为了长时间 fuzz 中按轮次采集，可以对 Nav2 进程发送 `SIGUSR1` 触发 coverage flush：

```bash
pgrep -f 'nav2_.*|controller_server|planner_server|bt_navigator|behavior_server|smoother_server|map_server|amcl' \
  | xargs -r kill -USR1
```

查看覆盖率文件是否生成：

```bash
find "$RUN_OUT/sancov" -type f -name '*.sancov' -print
```

查看 TSAN 报告：

```bash
find "$RUN_OUT/tsan" -type f -name 'tsan.*' -print
grep -R "WARNING: ThreadSanitizer\\|SUMMARY: ThreadSanitizer" "$RUN_OUT/tsan"
```

## 10. 验证插桩是否真正生效

检查二进制是否链接 TSAN：

```bash
readelf -d "$NAV2_WS/install_sancov/nav2_planner/lib/nav2_planner/planner_server" \
  | grep -E 'libtsan|RUNPATH|RPATH'
```

检查是否存在 SanitizerCoverage 符号：

```bash
nm -D "$NAV2_WS/install_sancov/nav2_planner/lib/nav2_planner/planner_server" \
  | grep '__sanitizer_cov'
```

启动 Nav2 后，成功现象包括：

```text
$RUN_OUT/tsan/tsan.*       # TSAN 报告文件，只有触发 warning 时才明显有内容
$RUN_OUT/sancov/*.sancov   # SanitizerCoverage 覆盖率文件
```

如果 fuzz 或测试程序能稳定驱动 Nav2，则应能观察到 `.sancov` 文件数量和大小随执行增长。

## 11. 常见问题

### 11.1 不要混用构建模式

TSAN-only、TSAN+SanitizerCoverage、普通构建、gcov/lcov 构建不能混用同一套 build/install 目录。切换模式时应清理对应目录：

```bash
rm -rf "$NAV2_WS/build_sancov" "$NAV2_WS/install_sancov" "$NAV2_WS/log_sancov"
rm -rf "$NAV2_WS/build_tsan" "$NAV2_WS/install_tsan" "$NAV2_WS/log_tsan"
```

### 11.2 不要写系统库

不要执行下面这种操作：

```bash
sudo make install
sudo colcon build --install-base /opt/ros/lyrical
```

正确做法是始终使用：

```bash
--install-base "$NAV2_WS/install_sancov"
```

### 11.3 ROS_DOMAIN_ID 不要过大

FastDDS 在 domain id 过大时可能报：

```text
Calculated port number is too high
```

建议使用较小 domain id，例如：

```bash
export ROS_DOMAIN_ID=42
```

### 11.4 `ros2 launch` 正常退出时出现 exit code -2

如果是测试 harness 或人工 Ctrl-C 结束 Nav2，日志里可能看到：

```text
process has died ... exit code -2
```

这通常是 SIGINT 关闭进程，不等价于 Nav2 crash。判断是否 crash 应结合 TSAN 报告、core dump、harness 统计和进程退出上下文。

## 12. 最小成功标准

一份可交付的 Nav2 插桩构建至少应满足：

- Nav2 从源码在本地 workspace 编译成功。
- `install_sancov/setup.bash` 可以被 source。
- `readelf` 能看到 TSAN runtime 链接。
- `nm` 能看到 `__sanitizer_cov` 相关符号。
- 运行 Nav2 后 `$RUN_OUT/sancov` 能生成 `.sancov` 文件。
- 触发并发问题时 `$RUN_OUT/tsan/tsan.*` 能生成 ThreadSanitizer 报告。

这就是我们成功使用的 Nav2 插桩路线：Clang 18 编译、TSAN 检测并发错误、SanitizerCoverage 输出覆盖率，全部通过本地 colcon workspace 完成，不污染系统 ROS 安装。
